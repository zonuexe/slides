型付け(typing) vs 型付き(typed)

  • プログラムを検査して、項(≒ 式, expression)のとりうる状態を

分類するのが型付け(typing)。型を明示しなくても項の種類を特定する具体的な手続きが型推論(type inference)。

  • 実行時に値の型チェックを行なうことを、

便宜的に動的型付け(dynamic typing)と呼ぶこともある

  • 静的な型付けによってとりうる状態が定まったプログラムのことを

「型付き(typed)」と呼ぶ

Page 28

いわゆる「型安全」(type safety)

  • 健全性(Soundness)と同じ意味
  • 濫用されがちな用語だが、概ね型に関する記述に矛盾がないことを保証でき

るようになっていることを表わしている

  • 「健全性がある」 実行したときに、型に関するエラーが起こらないといえる
  • 「健全性がない」 実行してみたときに、エラーが起こりかねない
  • C言語全般、Javaの「ぬるぽ」、TypeScriptのany/asや配列など

Page 29

言語が静的か動的かとは[独自研究]

  • ある言語の仕様または標準的な処理系によって構造が事前に検証されている

ことが前提になっている言語が静的(型付き)

  • 事前検証が前提ではなく、実行時(run-time)に構造が決定されるのが動的
  • 一般的にはコンパイラ vs インタプリタに一致するが、必ずしもそうではない
  • 静的言語にも多かれ少なかれ動的な機能が存在し、グラデーションは大きい
  • 動的言語でもPHP, Python, Ruby, JavaScriptで動的要素が全然違う

Page 30

TypeScriptにとっての型

  • 型宣言をもとに型チェックを行なって、分析情報を報告
  • 実行時には型情報は何も残らない
  • JavaScriptにコンパイル ≒ 型定義の部分をひっぺがして実行
  • Node.js 25.2ではType Strippingで直接実行できるようになった
  • 実際にはTypeScript enum など別のコード生成をする機能もある
  • 型がついたコードは実行時にはエラーが出ないでほしい(願望)

Page 33

型理論から見たPHPインタプリタ

  • 型が合わない（Ill-typed）コードであっても、エラーとして弾かれず、

正当なプログラム（構文木）として受理される → 実行時エラー

  • 関数は型宣言に拘らず、任意の値を返そうとすることができる
  • プロパティは型宣言に拘らず、任意の値を代入しようとすることができる
  • ローカル変数に型宣言はなく、任意の型の値を代入可能
  • オペコードコンパイラは実行前にプログラムの健全性を「証明」しない

Page 34

実行時のインタプリタの振る舞い

  • PHP処理系(ZendVM)内では、zval構造体に型タグを保持している
  • 常に is_int() のような関数で型を識別できる
  • 型宣言と反した値が渡されると、キャストまたは実行時エラーが起こる
  • いわゆる「強い型付け」であり、実行時に型がとり違えられることはない
  • RTTI(実行時型情報)は型理論における(静的な)型ではない
  • 言語セマンティクスとしては型なしだが、JITは静的型情報を活用する

PHPと型宣言

  • 引数などのデータ型を表わす手段としてコメントにPHPDocを書く文化
  • PHP 5.xで関数／メソッドのパラメータに「型ヒント」が書けるようになった
  • array, callable, クラス名, インターフェイス名だけを書けた
  • PHP 7.0で正式に「型宣言」としてスカラー型宣言と戻り値型が記述可能に
  • PHP 8.0以降でユニオン型宣言などが機能追加

Page 47

PHPの型宣言の特徴

  • コードごとに declare(strict_types=1); が宣言できる
  • 引数とデータ型の種類を厳密にチェックしてTypeErrorを出す
  • デフォルト(無宣言)では、 add("1", "2”) を add(1, 2) としてキャスト
  • add(“a”, “b”) のような数値ではない文字列はTypeErrorになり安心
  • add((int) $a, (int) $b); のようなコードとは安全性のレベルが違う

Page 115

PHPが静的型付きと言える条件

  • 静的解析やユニットテストなどのCIチェックした上でデプロイされている
  • PHPStan, Psalm, Phan, Magoなど… Lv.maxかどうかは問わない
  • ユニットテストで十分なカバレッジのテストが網羅されている
  • ツールの種類×プロジェクトが静的に信頼に足る状況にできるかが大きい
  • 静的型付きの言語を使っていても本番で健全性がないコードにできる
  • PHPは動的言語の中では実行時バリデーションのお蔭で問題が隠れない
